世界模型 04｜从视频生成到动作与决策
World Models 04 · From Video to Action

A convincing future is only the beginning / 可信的画面，只是起点
Watch a generated hand reach toward a cup, and the scene may look completely convincing. But what exactly has the model demonstrated? Perhaps it produced a plausible movie from a prompt. Perhaps it predicted how a particular action changes the scene. Or perhaps those predictions helped a real robot choose a successful action. These are different tests, requiring different evidence. The original Sora report already showed why: impressive video generation can coexist with incorrect physics and missing object state changes.
看一只生成的人手伸向杯子，整个场景可能非常逼真。但模型究竟证明了什么？它也许只是根据提示生成了一段合理的视频。也许它预测了某个具体动作怎样改变场景。也可能这些预测确实帮助真机器人选出了成功的动作。这是不同的测试，需要不同的证据。最初的 Sora 研究报告已经说明：出色的视频生成，也可能伴随错误物理和物体状态缺失。
https://openai.com/index/video-generation-models-as-world-simulators/

Ask what changes when the action changes / 换一个动作，未来会怎样
Hold the starting observation fixed and compare two possible commands. One moves the gripper left; the other closes it. An action-conditioned world model should predict different consequences for those inputs. The control must have a defined meaning, whether it is a game key or a robot displacement. A text description of movement is a useful condition, but it does not automatically specify a calibrated motor command. This action interface is the first connection to inspect when comparing video models.
固定起始观测，比较两个可能的指令。一个让夹爪向左移动，另一个让夹爪闭合。动作条件世界模型应该为这两个输入预测不同后果。控制量必须有明确含义，可能是游戏按键，也可能是机器人位移。动作的文字描述可以作为条件，但不会自动变成经过标定的电机指令。比较视频模型时，首先要检查的就是这个动作接口。

Predict useful features / 预测有用的特征
V-JEPA 2 takes a different route: its prediction target is a representation, rather than every future pixel. Read the original figure from left to right. First, an encoder sees a partially masked video, and a predictor estimates features for the missing regions. The targets come from an exponential moving average encoder. This stage learns visual representations from large amounts of video. The separate action-conditioned stage then freezes the encoder and learns how robot actions and poses change those features.
V-JEPA 2 走了另一条路线：预测目标是表征，而不是未来的每个像素。从左到右读这张原图。首先，编码器观察部分被遮挡的视频，预测器估计缺失区域的特征。预测目标来自指数移动平均编码器。这一阶段从大量视频中学习视觉表示。随后独立的动作条件阶段冻结编码器，学习机器人动作和位姿怎样改变这些特征。
https://arxiv.org/pdf/2506.09985v1

Unlabeled does not mean action-free / 无标签，不等于没有动作信息
The robot stage uses under sixty-two hours from DROID, but the word unlabeled needs care. It means the training does not need task names, rewards, or success labels. The videos still include end-effector position, orientation, and gripper state. Differences between consecutive states define seven-dimensional action inputs. The predictor learns both from observed feature histories and from short rollouts of its own predictions. So this is learning without task annotation, not learning physical robot control from completely action-free internet video.
机器人阶段使用不足六十二小时的 DROID 数据，但“无标签”需要准确理解。它指训练不需要任务名称、奖励或成功标签。视频仍然配有末端位置、朝向和夹爪状态。相邻状态之差构成七维动作输入。预测器既学习真实观测的特征历史，也学习将自身预测继续向前滚动。因此，这是不依赖任务标注的学习，并不是只靠完全没有动作信息的网络视频学会机器人控制。
https://arxiv.org/pdf/2506.09985v1

Turn predictions into a decision / 把预测变成决策
Now follow the planning diagram. The current image and the goal image are encoded into the same feature space. Candidate action sequences produce candidate future features. The cross-entropy method repeatedly samples actions and refines the distribution around candidates that approach the goal. The robot executes only the first action, observes the result, and plans again. This closes the loop through real observations. The world model predicts consequences; the optimizer selects actions according to the chosen goal-distance objective.
现在沿着规划图往下看。当前图像与目标图像被编码到同一特征空间。候选动作序列产生各自对应的未来特征。交叉熵方法反复采样动作，并围绕更接近目标的候选调整分布。机器人只执行第一步，观察结果，再次规划。真实观测就这样构成闭环。世界模型预测后果；优化器按照选定的目标距离函数选择动作。
https://arxiv.org/pdf/2506.09985v1

Read the robot evidence precisely / 准确读懂机器人证据
V-JEPA 2-AC was tested on physical Franka arms in two laboratories, including reaching, grasping, and pick-and-place. Pick-and-place used several supplied image subgoals. Zero-shot here means no extra training data from those target laboratories. It does not mean the model had never seen robot trajectories. And the reported comparison used sixteen seconds to plan one action on a single GPU. That is evidence for a particular planning system, with camera and horizon limitations, not a claim of real-time universal manipulation.
V-JEPA 2-AC 在两间实验室的实体 Franka 机械臂上测试了到达、抓取和取放。取放使用了外部提供的多个图像子目标。这里的零样本指没有额外使用目标实验室的训练数据。它并不表示模型从未见过机器人轨迹。论文中的对照设置还需要在单张 GPU 上用十六秒规划一个动作。这证明了一个具体规划系统的能力，同时仍有相机和时域限制，不能直接称为实时通用操作。
https://arxiv.org/pdf/2506.09985v1

Discover a control from video / 从视频里发现控制量
Genie starts from a different missing ingredient: internet video often lacks the actions that produced it. Its latent-action model compresses changes between frames into discrete codes. The video tokenizer describes the scene, while the dynamics model combines visual tokens with the selected action code. At inference, choosing a code influences the next generated frame. This makes video-only learning interactive, but the code is not automatically a robot command in meters or radians. That physical correspondence would still need to be established.
Genie 面对的是另一种缺失：网络视频通常没有记录产生画面的动作。它的潜动作模型把帧间变化压缩为离散编码。视频 tokenizer 描述场景，动力学模型再把视觉 tokens 与选定的动作编码结合。推理时，选择哪个编码会影响下一张生成图像。这让纯视频学习具有交互性，但编码不会自动成为以米或弧度计量的机器人命令。这种与物理控制量的对应关系仍需要另外建立。
https://arxiv.org/pdf/2402.15391

From short rollouts to interactive worlds / 从短序列到交互世界
The Genie generations show a progression in interaction, not a single interchangeable model. The first paper reported about one frame per second and sixteen frames of memory. Genie 2 accepts keyboard and mouse controls from an initial image; most published examples lasted ten to twenty seconds. Genie 3 extended this to interactive scenes lasting minutes at seven-twenty-p resolution. Its current official page reports twenty to twenty-four frames per second. These figures describe specific releases, not guarantees for every generated world.
Genie 各代展示的是交互能力的演进，不能把它们视作一个可互换的模型。第一代论文报告大约每秒一帧，以及十六帧记忆。Genie 2 从初始图像出发，接受键盘与鼠标控制；多数公开例子持续十到二十秒。Genie 3 将其扩展到持续数分钟、七百二十 p 分辨率的交互场景。当前官方模型页报告每秒二十到二十四帧。这些数值描述具体版本，并不是对每一个生成世界的保证。
https://arxiv.org/pdf/2402.15391

Memory is more than a smooth camera / 记忆，不只是镜头平滑
Consider painting a wall, turning away, and returning. A consistent world should preserve where the paint went, rather than inventing a fresh wall. This is why revisitation demonstrations are more informative than a smooth forward camera movement. But visual persistence alone does not establish correct forces, collisions, or every possible interaction. Genie 3 still documents a limited action space and difficulty with multiple independent agents. SIMA completing goals inside that generated world is virtual-agent evidence, which must remain separate from physical robot validation.
想象给墙涂色，然后转身离开，再回头。一致的世界应该保留油漆的位置，而不是重新编造一面墙。因此，回访场景的演示，比镜头一直平滑向前更能说明问题。然而，视觉信息持续存在，并不能证明力、碰撞或任意交互都正确。Genie 3 仍明确说明动作空间有限，多独立智能体交互也有困难。SIMA 在生成世界里完成目标，属于虚拟智能体证据，必须与实体机器人验证分开。
https://deepmind.google/blog/genie-3-a-new-frontier-for-world-models/
https://deepmind.google/models/genie/

When visual details change learning / 视觉细节怎样影响学习
Now switch from providing an interactive world to training a policy inside one. IRIS encodes game images as discrete tokens and predicts future tokens, rewards, and episode endings. Its policy learns from those imagined trajectories. DIAMOND instead predicts future images with conditional diffusion. The original comparison highlights small visual inconsistencies, including bricks and reward objects. Losing such details can change the learning signal, even when the overall picture looks similar. These are Atari experiments under specified data budgets, not measurements of physical robot competence.
现在从提供交互世界，转向在世界模型内部训练策略。IRIS 将游戏图像编码为离散 tokens，并预测未来 tokens、奖励和回合结束。策略从这些想象轨迹中学习。DIAMOND 则用条件扩散预测未来图像。这张原始对比图标出了细小的不一致，包括砖块和奖励物体。即使整体画面看起来相似，丢掉这些细节也可能改变学习信号。这些是限定数据预算的 Atari 实验，不是实体机器人能力的测量。
https://arxiv.org/pdf/2209.00588
https://arxiv.org/pdf/2405.12399

Two clocks inside a diffusion world / 扩散世界里的两只时钟
A diffusion world model has two different clocks. Environment time advances when an action leads to the next observation. Denoising time counts the internal refinement steps used to produce that observation. DIAMOND used three denoising steps in its main Atari experiments. Its separate Counter-Strike demonstration used fixed human gameplay data and human keyboard controls, without training an RL agent there. A playable video can therefore demonstrate a learned environment while saying little about the quality of a learned policy.
扩散世界模型里有两只不同的时钟。动作带来下一次观测时，环境时间向前推进。去噪时间则记录生成这次观测需要多少内部修正步骤。DIAMOND 的主要 Atari 实验使用三步去噪。另一个 Counter-Strike 演示使用固定的人类游戏记录和真人键鼠控制，并没有在其中训练强化学习代理。因此，一段可玩的生成视频能够展示学到的环境，却未必说明学到的策略有多好。
https://arxiv.org/pdf/2405.12399
https://diamond-wm.github.io/

Read the Cosmos version and interface / 先看 Cosmos 的版本与接口
Cosmos is a family, so attach a version and an interface to every claim. The earlier platform combined video curation, tokenizers, foundation models, and adaptation tools. Predict generates future video; Transfer conditions visual generation on spatial inputs; Reason supports physical reasoning in language. But these are not permanent walls between capabilities. By early twenty twenty-six, Predict 2.5 also had robot action-conditioned and policy recipes. A useful comparison names the actual checkpoint, its training data, its outputs, and its evaluation environment.
Cosmos 是一个家族，每项结论都应带上版本和接口。早期平台包含视频整理、tokenizer、基础模型和适配工具。Predict 生成未来视频；Transfer 用空间输入约束视觉生成；Reason 支持语言形式的物理推理。但这些用途之间并非永远不变的边界。到了二〇二六年初，Predict 2.5 也提供了机器人动作条件与策略配方。有用的比较必须明确具体权重、训练数据、输出，以及评测环境。

One backbone, different prediction jobs / 同一个骨干，不同预测任务
Cosmos 3 makes that connection explicit through a shared architecture for understanding, generation, and actions. Its original diagram combines an autoregressive stream with a diffusion stream. Change what is observed and what must be predicted, and the task changes. Given actions, predict video: forward dynamics. Given visual changes, infer actions: inverse dynamics. Jointly predict actions and video: a policy configuration. The DROID post-trained policy has physical robot evidence; that evidence belongs to the adapted policy, rather than automatically to every base-model output.
Cosmos 3 通过共享理解、生成和动作的架构，让这种联系更加明确。原图将自回归分支与扩散分支结合起来。改变哪些量已知、哪些量需要预测，任务就会改变。给定动作，预测视频：这是正动力学。给定视觉变化，推断动作：这是逆动力学。同时预测动作和视频：这是策略配置。经过 DROID 后训练的策略有实体机器人证据；这些证据属于适配后的策略，不会自动适用于基础模型的每一种输出。
https://research.nvidia.com/labs/cosmos-lab/cosmos3/technical-report.pdf

Choose the evidence for the job / 按用途选择证据
When choosing a world model, begin with the job you need it to do. For data generation, inspect coverage and whether useful structure survives. For planning, inspect action calibration, rollout errors, and measured decision latency. For imagined policy learning, evaluate the resulting policy in the original environment. For robotics, report physical task outcomes separately from image scores and simulated successes. A beautiful prediction becomes useful when its particular interface and evidence match the decision you want to make.
选择世界模型时，先从你需要它完成的工作出发。用于数据生成，就检查覆盖范围，以及有用结构是否保留。用于规划，就检查动作标定、滚动预测误差和实测决策延迟。用于想象训练，就回到原环境评测训练出来的策略。用于机器人，就把实体任务结果与图像分数、仿真成功分开报告。当一个预测的具体接口与证据，匹配你真正要做的决策时，它才变得有用。
